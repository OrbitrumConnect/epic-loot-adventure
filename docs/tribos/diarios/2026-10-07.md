## Sessão 5 — Acampamentos inimigos + objetivos idle/manual

Pedido do Caio: preencher o mapa com acampamentos de inimigos e poder clicar nos objetivos
para executá-los em modo **idle** (piloto automático) ou **manual**.

### Investigação do mundo 3D (antes de escrever código)

| Achado | Onde | Consequência |

Ninguém nunca escreve um destino ali | O piloto automático escreve nesse ref em vez de criar um sistema de movimento novo |

| Única constante de módulo | `MAP_HALF = 45` | O resto são números soltos dentro das funções |

### Desenho (decisão minha, revisável pelo Pedro)

Contrato de tipos escrito antes de delegar: `src/game/types/camp.ts` e `src/game/types/objective.ts`.

A peça central é `decideIntent(snapshot, now): AutoIntent` — função **pura e determinística** que
responde "o que fazer agora": `move`, `attack`, `gather`, `heal`, `retreat` ou `idle`. Quem decide
é o sistema; quem executa é o laço de quadro do mundo 3D. Mesma separação da cidade, e pronta para
migrar ao servidor quando houver autoridade.

Prioridade do piloto automático: morto → curar → recuar → defesa própria (inimigo perseguindo) →
objetivo ativo da fila → ocioso. **Defesa própria vem antes da fila**: ser atacado interrompe a tarefa.

Modo `manual` x `idle` fica na fila de objetivos (`ObjectiveQueueState.mode`). Qualquer tecla WASD
derruba para `manual` na hora — o jogador sempre tem a palavra final.

### Erro pré-existente encontrado (avisar o Pedro)

No servidor de desenvolvimento o console acusa `R3F: Cannot set "data-tsd-source"` e o canvas cai no
error boundary antes de se recuperar. **Não é desta sessão**: reproduzi o mesmo erro no commit anterior
(`875a51e`). A causa é o plugin de devtools do TanStack, embutido no `@lovable.dev/vite-tanstack-config`,
que injeta `data-tsd-source` em todo elemento JSX; o React Three Fiber tenta aplicar esse atributo nos
objetos Three e quebra. O erro de `useLayoutEffect` que aparece junto é consequência: o React recria a
árvore e os hooks se desalinham.

**Não afeta o jogo entregue:** `npx vite build` passa e o atributo não existe em `.output/`. Mexer nisso
significaria alterar o `vite.config.ts`, que é do Lovable e traz aviso explícito para não ser tocado —
fica como decisão do Pedro.

Também anotado: `npx vite preview` não sobe neste projeto (procura `dist/server/server.js`, o build gera
`.output/`). Igualmente pré-existente.
